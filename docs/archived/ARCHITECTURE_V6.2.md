# ASR/OCR 배치 처리 아키텍처 (V6.2)

## 개요

LiteLLM 중앙집중 리소스 관리 기반의 GPU/NPU 하이브리드 아키텍처입니다.

- **리소스 충돌 방지**: LiteLLM Gate가 SETNX로 동일 리소스 동시 접근 차단
- **GPU/NPU 선택**: accuracy_mode에 따라 자동 라우팅
- **On-demand 서버**: Provider Manager가 PM2로 서버 생명주기 관리
- **GPU 포트 분리 (V6.2)**: LLM(8080)과 OCR Vision(8081) 모델 스왑 없이 독립 운영

## Prometheus 기반 동적 라우팅

LiteLLM Chat 요청 시 Prometheus 메트릭을 조회하여 GPU/NPU 사용량에 따라 동적으로 라우팅합니다.

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                     infra/litellm/custom_handler.py                             │
│                                                                                 │
│  select_provider_async() / select_provider_sync()                               │
│                                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐   │
│  │  1. Prometheus Query                                                    │   │
│  │     - GPU: windows_gpu_engine_utilization_percentage (device: 0x142B6) │   │
│  │     - NPU: windows_gpu_engine_utilization_percentage (device: 0x160E6) │   │
│  │                                                                         │   │
│  │  2. 라우팅 로직 (BUSY_THRESHOLD = 70%)                                  │   │
│  │     ┌─────────────────────────────────────────────────────────────┐    │   │
│  │     │  if npu_avg < 70%:                                          │    │   │
│  │     │      → NPU (flm-llm-server:11435)                           │    │   │
│  │     │  elif gpu_avg < 70%:                                        │    │   │
│  │     │      → GPU (llama-server:8080)                              │    │   │
│  │     │  else:                                                      │    │   │
│  │     │      → wait & retry (양쪽 모두 바쁨)                        │    │   │
│  │     └─────────────────────────────────────────────────────────────┘    │   │
│  └─────────────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 라우팅 방식 비교

| 작업 유형 | 라우팅 방식 | 처리 위치 | 설명 |
|----------|------------|----------|------|
| LLM Chat | Prometheus 동적 | `custom_handler.py` | 사용량 기반 GPU/NPU 자동 선택 |
| ASR | accuracy_mode 명시 | `run_proxy.py` | Worker가 resource_type 지정 |
| OCR | accuracy_mode 명시 | `run_proxy.py` | Worker가 resource_type 지정 |
| Diarization | GPU 고정 | `run_proxy.py` | pyannote는 GPU만 지원 |

## GPU vs NPU 선택 기준

| Mode | Resource | 특징 |
|------|----------|------|
| `accuracy_mode="speed"` | NPU (FLM) | 빠름, 저전력, 4B 모델 |
| `accuracy_mode="accuracy"` | GPU | 고품질, 고성능, 8B+ 모델 |

## 핵심 포인트

1. **리소스 충돌 방지**: LiteLLM Gate가 SETNX로 동일 리소스 동시 접근 차단
2. **Prometheus 동적 라우팅**: LLM Chat 요청 시 GPU/NPU 사용량 기반 자동 분배
3. **ASR 병렬 처리**: ASR과 Diarization이 ThreadPoolExecutor로 동시 실행
4. **OCR→LLM 순차**: OCR 완료 후 Backend가 LLM 요약 작업 큐잉
5. **On-demand 서버**: Provider Manager가 idle timeout 후 서버 자동 중지
6. **GPU 포트 분리 (V6.2)**: llama-server(8080)와 llama-ocr-server(8081) 분리로 모델 스왑 없이 병렬 요청 처리
