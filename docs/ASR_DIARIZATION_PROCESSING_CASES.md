- **실행 시간**: 415.99초

- **ASR 시간**: 330.74초 (로드: 0초 + 전사: 330.74초)
- **처리 속도**: 2.12x 실시간
- **화자 수**: 6명 (SPEAKER_00~05)

**특징**:
- ✅ ASR 내부 병렬 처리로 약간의 시간 절약
- ✅ 화자분리 결과를 기반으로 최적 분할 지점 선택

**분할 전략**:

## 주요 발견 사항

### 1. ASR 내부 병렬 처리 효과 미미

- **케이스 1 vs 케이스 2**: ASR 분할 병렬 처리로 인한 시간 절약이 거의 없음 (0.39초)
- **원인**: Whisper는 내부적으로 30초 청크를 순차 처리하므로, 외부에서 파일을 분할해도 GPU 리소스 경쟁과 오버헤드로 인해 효과가 제한적

### 2. 병렬 처리의 효과

- **케이스 3이 가장 빠름**: 화자분리와 ASR을 병렬 실행하여 총 시간을 최소화
- **GPU 리소스 경쟁**: 병렬 실행 시 각 작업의 개별 시간은 증가하지만, 전체 시간은 단축됨
- **최적 전략**: 케이스 3 (화자분리와 ASR 분할 병렬 동시 실행)

### 3. GPU 드라이버 스택 차이

- **Vulkan (whisper.cpp)**: ASR 처리에 사용
- **ROCm (PyTorch)**: 화자분리 처리에 사용
- **병렬 처리 가능**: 서로 다른 드라이버 스택으로 인해 실제 병렬 실행 가능
- **하지만 GPU 리소스 경쟁**: 동일 GPU를 공유하므로 타임슬라이싱으로 인한 성능 저하 발생

### 4. 화자분리 결과 기반 분할의 효과

- **케이스 2**: 화자분리 결과를 기반으로 최적 분할 지점 선택
- **케이스 3**: 화자분리 결과 없이 중간 지점으로 분할
- **결과**: 분할 전략의 차이가 전체 처리 시간에 큰 영향을 미치지 않음

**케이스 3 (화자분리와 ASR 분할 병렬 동시 실행)**이 가장 빠른 처리 시간을 보여줍니다.

**장점**:

**단점**:
- GPU 리소스 경쟁으로 인한 개별 작업 시간 증가
- ASR 분할 병렬 처리의 효과가 제한적

### 권장 사항

1. **기본 설정**: 케이스 3 사용
   - 가장 빠른 처리 시간
   - 실용적인 성능 향상

2. **정확도 우선**: 케이스 1 사용
   - ASR이 전체 파일 컨텍스트를 사용
   - GPU 리소스 경쟁 없음

3. **균형**: 케이스 4 사용
   - 병렬 처리의 이점
   - ASR 전체 파일 컨텍스트 유지

### 향후 개선 가능성

1. **ASR 내부 병렬 처리 최적화**: Whisper의 청크 처리 방식을 고려한 더 효율적인 분할 전략
2. **GPU 스케줄링 최적화**: Windows GPU 스케줄러 설정 조정
3. **메모리 관리**: GPU 메모리 할당 전략 최적화

### 해석

- **처리 속도**는 두 케이스 모두 2.6x 이상으로, 56분 오디오도 약 21~22분 내에 처리 가능했습니다.
- 케이스 3은 병렬 실행으로 총 시간을 줄이려 했으나, 화자분리·ASR 모두 장시간 GPU를 점유하면서 개별 시간이 크게 늘어나 오히려 케이스 2보다 15초가량 느렸습니다.
- **장시간 파일에서는 케이스 2가 더 안정적**입니다. 화자분리를 끝낸 뒤 ASR 병렬을 수행하기 때문에 GPU 경쟁이 덜하고, 메모리 사용량도 더 낮게 유지되었습니다.
