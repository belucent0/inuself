# 🔨 현재 개발 중인 항목

## 0) 현재 스프린트 운영 기준 (2026-02)

- 모든 개발 항목은 아래 3가지를 함께 관리:
  - **산출물**: 코드/문서/스크립트가 남는지
  - **측정값**: 품질 판단 가능한 수치가 있는지
  - **완료 조건(DoD)**: 끝났다고 말할 수 있는 기준이 있는지

### 이번 스프린트 실행 체크리스트 (운영)

- [ ] 검색 품질 기준선 케이스셋(30~50개) 고정 파일 생성
- [ ] 품질 측정 결과 JSON/MD 리포트 템플릿 통일
- [ ] 재시도 정책 변경 전/후 비교 리포트 1회 생성
- [ ] 로드맵/트러블슈팅 문서 동기화 규칙 적용

## 1) 검색 품질 운영 자동화 (AI Chat)

최근 검색 파이프라인 고도화는 반영되었고, 현재는 "지속 운영" 단계로 전환 중입니다.

**현재 상태:**
- 검색/재검색/리랭크/교차언어 fallback은 서비스 반영 완료
- 품질 측정 스크립트(`scripts/*quality*`, `scripts/eval_threads_from_api.py`)는 준비됨
- 정기 회귀 측정 루틴(주기/기준치/리포트 템플릿)은 미완료

**다음 액션(우선순위 순):**
- **품질 기준선 고정**: 대표 질문 세트(국문 중심 + 다국어 혼합) 30~50개 고정
- **지표 리포트 표준화**: 검색 커버리지, 저품질 재시도율, 최종 응답 근거밀도 지표를 동일 포맷으로 저장
- **튜닝 규칙 명시**: `AGENT_SEARCH_WEB_LIMIT`, `AGENT_HYBRID_WEB_LIMIT`, `AGENT_CONTENT_FETCH_TOP_K` 변경 규칙 문서화
- **회귀 게이트 도입**: 기준선 대비 품질 하락 시 배포 전 경고

**완료 조건(DoD):**
- 동일 케이스셋으로 2회 연속 측정 시 리포트 형식/지표가 일관됨
- 파라미터 변경 전/후 비교 리포트가 자동 생성됨
- 저품질 재시도 정책 변경 시 영향도를 수치로 설명 가능

**현재 남은 핵심 공백:**
- 케이스셋 버전 관리 규칙(추가/삭제 기준) 미정
- 리포트 저장 위치/보존 기간 규칙 미정
- 품질 하락 임계값(알림 기준) 미정

## 2) ASR 청킹 오버랩 LLM 정밀 후처리

ASR 청크 경계에서 발생하는 끊김/중복 표현을 줄이는 작업입니다.

**세부 작업:**
- **오버랩 추적 구조화**: 청크별 overlap span과 원문 인덱스 매핑
- **후처리 프롬프트 분리**: 일반 교정과 경계 교정을 별도 템플릿으로 분리
- **머지 규칙 추가**: 문장 단위 우선 병합 + 시간축 역전 방지

**검증 계획:**
- 10분 이상 오디오 샘플 20개로 경계 오류율 비교
- 중복 토큰율, 문장 끊김율, 수동 샘플 평가 점수 기록

**완료 조건(DoD):**
- 경계 오류율이 기존 대비 유의미하게 감소
- 회귀 테스트에서 전체 전사 누락률 악화 없음

**의존성/리스크:**
- LLM 후처리 호출량 증가에 따른 처리시간 상승 가능
- 긴 오디오 샘플에서 세그먼트 병합 규칙이 과도하게 작동할 가능성

## 3) Whisper 신뢰도 기반 환각 제거 + LLM 보정

신뢰도 낮은 구간만 선택적으로 보정해 비용과 품질을 균형화합니다.

**세부 작업:**
- **신뢰도 수집**: logprob/segment confidence를 표준 필드로 저장
- **의심 구간 감지**: 반복어, 비문, 언어 불일치 패턴 룰 추가
- **선택적 LLM 보정**: 저신뢰 구간만 후처리 대상으로 라우팅

**검증 계획:**
- 일반 구간 오버-보정(불필요 수정) 비율 측정
- 저신뢰 구간에서만 정밀도 향상되는지 분리 검증

**완료 조건(DoD):**
- 전체 처리 시간 급증 없이 저신뢰 구간 품질 개선
- 보정 후 환각성 문구 비율 감소

**의존성/리스크:**
- 모델별 confidence 스케일 차이로 임계값 이식성이 낮을 수 있음
- 규칙 기반 감지와 LLM 보정 규칙 충돌 시 과보정 발생 가능

## 4) WPI 심리검사 기반 동적 리포팅 생성

상담/코칭 시나리오에서 바로 활용 가능한 리포트 자동화를 구현합니다.

**세부 작업:**
- **도메인 모델 정교화**: `PsychologyAnalysis` 스키마 확장, 버전 필드 명확화
- **파이프라인 단계화**: 화자 분류 -> 표현 추출 -> WPI 해석 -> 리포트 렌더
- **재실행/비교 기능**: 동일 콘텐츠 재분석 시 버전 diff 제공

**완료 조건(DoD):**
- 동일 입력에서 재현 가능한 리포트 구조 확보
- 상담/코칭 실무 피드백 루프(수정 요청 -> 재분석) 동작

**의존성/리스크:**
- 도메인 해석 규칙 변경 시 과거 리포트와의 버전 정합성 이슈
- 리포트 표현 문구의 일관성/근거 추적성 유지 필요

## 5) 다중 이미지 스토리텔링 및 심층 분석

다중 이미지 입력에서 순서/맥락 기반 설명 품질을 높이는 작업입니다.

**세부 작업:**
- **입력 UX**: 최대 5장 선택 + 순서 변경 UX 정식 반영
- **개별 분석 표준화**: OCR/Portray 결과 스키마 통일
- **통합 스토리 생성**: 이미지 간 인과/시간 흐름 반영 요약

**완료 조건(DoD):**
- 이미지 순서 변경 시 스토리 결과가 의도대로 달라짐
- 개별 분석 근거와 통합 요약 근거를 분리 제시 가능

**의존성/리스크:**
- OCR/Portray 출력 포맷 불일치 시 통합 요약 품질 저하
- 업로드/정렬 UX 변경 시 모바일 사용성 회귀 가능
