# 🎯 장기 도전 과제

## 장기 과제 운영 원칙

- 장기 과제는 즉시 구현보다 "검증 가능한 중간 단계"를 먼저 정의
- 반기(6개월) 단위로 목표/리스크/비용을 재산정
- 장기 과제라도 단기 PoC 결과가 누적되면 `ROADMAP_CONSIDERING.md`로 하향/전환 가능

## 1) Whisper 모델 경량화 + 정확도 보존

Whisper 모델 크기/연산량을 줄이면서 한국어 품질 저하를 최소화하는 과제입니다.

**장기 목표:**
- 온디바이스/저사양 환경에서 실사용 가능한 추론 속도 확보
- 기존 정확도 대비 유의미한 하락 없이 운영 가능 수준 달성

**핵심 트랙:**
- 모델 양자화(정밀도/속도 트레이드오프 실험)
- 한국어 중심 Distillation 전략 검토
- 도메인 특화 파인튜닝(회의/상담/인터뷰 음성)

**완료 기준(장기):**
- 기준 데이터셋에서 정확도 저하를 허용 범위 내로 유지
- 비용/지연 개선 효과가 운영 관점에서 명확할 것

**예상 기간:** 6개월 이상

---

## 2) 멀티모달 상담/코칭 Copilot 고도화

음성/문서/이미지 분석 결과를 결합해 상담/코칭을 지원하는 Copilot 수준으로 확장하는 과제입니다.

**장기 목표:**
- 단일 결과 제공이 아닌 "근거 + 추론 + 실행 제안"까지 연결
- WPI 분석, 대화 요약, 리스크 시그널을 통합 제공

**핵심 트랙:**
- 멀티소스 근거 정렬(시간축 + 화자축 + 문서축)
- 사용자 피드백 기반 개인화 리포트 개선 루프
- 설명 가능성(why this suggestion) 강화

**예상 기간:** 6~12개월

---

## 3) 온프레미스 추론 운영 표준화

Windows host + Docker bridge + provider manager 기반 운영을 더 안정적으로 표준화하는 과제입니다.

**장기 목표:**
- 모델/드라이버/런타임 버전 관리 체계 고도화
- 장애 시 빠른 복구를 위한 표준 운영 플레이북 구축

**핵심 트랙:**
- 배포 단위별 health check 및 자동 롤백 조건 정리
- 워커/백엔드/브리지 간 책임 경계 문서화
- 성능 회귀 탐지 자동화

**예상 기간:** 6개월 이상

---

## 4) 장기 과제 검증 마일스톤 템플릿

각 장기 과제는 아래 템플릿으로 마일스톤을 기록합니다.

- **M1 (탐색):** 요구사항/성능 목표/비용 목표 수치화
- **M2 (PoC):** 제한된 데이터로 기능 가능성 및 리스크 검증
- **M3 (확장):** 실제 워크로드 일부에 적용해 운영성 확인
- **M4 (전환):** 정식 로드맵(`developing` 또는 `considering`)으로 이동 여부 결정
