# 💭 개발 고려 중인 항목

아래 항목은 "좋은 아이디어" 수준이 아니라, 착수 전 확인해야 할 조건과 보류 이유를 명시한 후보 목록입니다.

## 운영 메모 (의사결정 규칙)

- 고려 항목은 분기마다 1회 재평가하며, 조건 충족 시 `ROADMAP_DEVELOPING.md`로 승격
- 승격 시 반드시 "착수 조건 충족 근거"와 "초기 검증 계획"을 함께 기록
- 2개 분기 연속 미진행 항목은 우선순위 재산정 또는 제거 검토

## 1) Linux 기반 GPU 가속 ASR 워커 지원

Linux 환경에서 GPU 가속 ASR(+화자분리) 워커를 공식 지원하는 과제입니다.

**착수 조건:**
- 운영 환경에 Linux 워커 도입 필요가 확정될 것
- ROCm 드라이버/의존성 버전 고정 전략이 마련될 것

**선행 검증:**
- Docker 이미지 빌드 재현성(클린 환경에서 3회 연속 성공)
- Windows 대비 처리속도/안정성 비교 벤치마크 확보

**보류 이유(현재):**
- 현 운영 포커스가 Windows host + provider bridge에 맞춰져 있음

---

## 2) 음성 프로필 기반 화자 인식

기존 diarization 결과를 개인 프로필과 매칭해 화자 이름까지 자동 인식하는 과제입니다.

**착수 조건:**
- 프로필 저장 정책(개인정보/보안/보존 기간) 합의
- 샘플 수집 및 라벨 품질 기준 수립

**선행 검증:**
- 소수 화자(3~5명) 폐쇄셋에서 1차 매칭 정확도 측정
- 오인식 시 fallback UX(이름 미확정 처리) 정의

**보류 이유(현재):**
- 기능 가치 대비 데이터 거버넌스/운영 부담이 큼

---

## 3) 실시간 스트리밍 화자분리

실시간 ASR 스트리밍에 화자 전환 추정까지 결합하는 과제입니다.

**착수 조건:**
- 목표 지연 시간 SLA 정의(예: N초 이내)
- 실시간 임베딩 추론 리소스 예산 확정

**선행 검증:**
- 짧은 윈도우(수 초)에서 화자 전환 감지 안정성 측정
- 화자 수 변화가 잦은 대화에서 플리커링 억제 전략 검증

**보류 이유(현재):**
- 현재는 정확도/안정성 우선으로 배치형 diarization에 집중

---

## 4) 영어 ASR 및 요약 콘텐츠 확장

영어 음성 입력에서 전사/요약 품질을 한국어와 유사 수준으로 끌어올리는 과제입니다.

**착수 조건:**
- 영어 데이터셋(도메인별) 확보
- 언어 감지 및 라우팅 정책 확정

**선행 검증:**
- 영어 전사 WER, 요약 품질 지표(정확성/압축률) 기준선 확정
- 다국어 혼합 발화에서 모드 전환 안정성 확인

**보류 이유(현재):**
- 검색 계층의 교차언어 fallback은 반영됐지만, ASR/요약 전체 파이프라인 다국어 최적화는 별도 큰 과제

---

## 5) 묵음 구간 감지 및 사용자 제안

묵음 구간을 자동 탐지해 삭제/건너뛰기 후보를 제안하는 생산성 기능입니다.

**착수 조건:**
- 클라이언트 성능 예산(파일 크기별 분석 시간) 확정
- UI 상 제안/적용 흐름 확정

**선행 검증:**
- 노이즈 환경에서 오탐률 측정
- 대용량 파일에서 브라우저 리소스 사용량 점검

**보류 이유(현재):**
- 핵심 전사/요약 품질 이슈 대비 우선순위가 낮음

---

## 6) LLM 기반 화자 분리 후처리

알고리즘 기반 diarization 결과를 문맥 기반으로 보정해 화자 일관성을 높이는 과제입니다.

**착수 조건:**
- 후처리 대상 범위(저신뢰 구간만 vs 전체) 결정
- 비용 대비 효율 기준 합의

**선행 검증:**
- 화자 교체 지점 오차 감소 효과를 정량 검증
- 3인 이상 다화자 대화에서 일관성 향상 여부 평가

**보류 이유(현재):**
- LLM 비용/지연 증가 리스크가 커서, 우선은 규칙 기반 개선을 선행

---

## 7) 검색 품질 운영 자동 튜닝 루프

검색 품질 지표를 기반으로 파라미터를 반자동 조정하는 운영 과제입니다.

**착수 조건:**
- 기준 질문 세트와 실패 케이스 태깅 체계 고정
- 튜닝 승인 절차(자동/수동) 정의

**선행 검증:**
- 자동 추천 파라미터가 수동 튜닝 대비 성능 하락을 일으키지 않는지 A/B 검증

**보류 이유(현재):**
- 먼저 수동 튜닝 루틴 안정화가 필요

---

## 후보 우선순위 (재평가 기준)

1. 영어 ASR 및 요약 콘텐츠 확장
2. 검색 품질 운영 자동 튜닝 루프
3. LLM 기반 화자 분리 후처리
4. 음성 프로필 기반 화자 인식
5. 실시간 스트리밍 화자분리
6. 묵음 구간 감지 및 사용자 제안
7. Linux 기반 GPU 가속 ASR 워커 지원

우선순위는 사용자 수요, 운영 비용, 데이터 준비 상태를 기준으로 재조정합니다.
