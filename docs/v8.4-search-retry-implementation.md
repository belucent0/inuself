## 개요

검색 결과가 불충분하거나 품질이 낮을 때 자동으로 쿼리를 재작성하여 재검색하는 메커니즘을 구현했습니다.

### 핵심 기능
1. ✅ **검색 품질 평가**: 결과 개수, 품질 점수, 관련성을 종합 평가
2. ✅ **적응형 쿼리 재작성**: 실패 원인에 따라 전략적으로 쿼리 변경
3. ✅ **루프 제어**: 최대 3회 재시도, 무한 루프 방지
4. ✅ **폴백 처리**: 모든 시도 실패 시 대안 제공
5. ✅ **조건부 엣지**: LangGraph의 순환 구조 활용

## 구현된 컴포넌트

### 1. State 확장
**파일**: `backend/app/agents/state.py`

```python
class GraphState(TypedDict):
    # ... 기존 필드들 ...

    # V8.4: 검색 재시도 관련
    search_retry_count: int              # 현재 재시도 횟수
    search_quality_score: float          # 검색 결과 품질 점수 (0-100)
    original_search_queries: list[str]   # 원본 검색 쿼리
    failed_queries: list[str]            # 실패한 쿼리 목록
    needs_retry: bool                    # 재시도 필요 여부
    retry_reason: str                    # 재시도 이유
```

### 2. SearchEvaluatorNode
**파일**: `backend/app/agents/nodes/search_evaluator.py`

**역할**: 검색 결과 품질을 평가하고 재시도 필요 여부 판단

**평가 기준**:
- 결과 개수 (40점): 0개=0점, 1개=10점, 3개=30점, 5개+=40점
- 품질 점수 (40점): Phase 3의 QualityAssessor 결과 활용
- 관련성 (20점): 키워드 매칭 비율

**재시도 판단**: 총점 50점 미만이면 재시도

### 3. QueryRewriterNode
**파일**: `backend/app/agents/nodes/query_rewriter.py`

**역할**: 실패 원인에 따라 쿼리를 재작성

**재작성 전략**:
1. **broaden**: 더 넓은 범위, 일반적인 용어 (1차 시도)
2. **narrow**: 더 구체적, 특정한 용어 (2차 시도)
3. **synonym**: 동의어, 관련어 사용 (3차 시도)

**적응형 전략**:
- `no_results` → broaden
- `low_quality` → trusted_domains
- `low_relevance` → keyword_boost

### 4. FallbackHandlerNode
**파일**: `backend/app/agents/nodes/fallback_handler.py`

**역할**: 모든 검색 시도 실패 시 대안 제공

**폴백 옵션**:
1. **llm_only**: 내장 지식으로 답변 (기본)
2. **rag**: 내부 문서 검색으로 전환
3. **explicit_error**: 사용자에게 명시적 안내

### 5. 그래프 통합
**파일**: `backend/app/agents/graph.py`

**새 함수**: `create_ai_graph_with_retry()`

**흐름**:
```
IntentParser
    ↓
Searcher ←────────┐
    ↓              │
SearchEvaluator    │
    ↓              │
[충분?]            │
 ├─ YES → Generator
 ├─ NO + retry<3 → QueryRewriter ─┘
 └─ NO + retry≥3 → FallbackHandler → Generator
```

```
질문: "TSMC 2026 투자 계획"

[1차 시도]
1. Searcher: 2개 결과
2. Evaluator: 45점 (불충분) → needs_retry=True, reason="insufficient_results"
3. QueryRewriter: "TSMC 투자", "반도체 투자 2026"

[2차 시도]
4. Searcher: 5개 결과
5. Evaluator: 68점 (충분) → needs_retry=False
6. Generator: 답변 생성
```

### 시나리오 3: 모든 시도 실패
```
질문: "xyzabc12345 최신 정보"

[1차 시도] Searcher: 0개 → Evaluator: 0점
[2차 시도] Searcher: 0개 → Evaluator: 0점
[3차 시도] Searcher: 0개 → Evaluator: 0점
[4차 시도] retry_count=3 (한계)

→ FallbackHandler: "검색 결과를 찾지 못했습니다. 내장 지식으로 답변합니다."
→ Generator: LLM 지식만으로 답변
```

## 기술적 세부사항

### LangGraph 루프 구현
```python
# Searcher → Evaluator (항상)
workflow.add_edge("searcher", "search_evaluator")

# Evaluator → 조건부 분기
def route_after_evaluation(state):
    if not state["needs_retry"]:
        return "generator"  # 충분
    elif state["search_retry_count"] < 3:
        return "query_rewriter"  # 재시도
    else:
        return "fallback_handler"  # 한계

workflow.add_conditional_edges(
    "search_evaluator",
    route_after_evaluation,
    {
        "generator": "generator",
        "query_rewriter": "query_rewriter",
        "fallback_handler": "fallback_handler",
    }
)

# Rewriter → Searcher (루프!)
workflow.add_edge("query_rewriter", "searcher")
```

### 무한 루프 방지
- `search_retry_count` 카운터
- `max_retries` 제한 (기본 3회)
- 3회 초과 시 자동으로 `fallback_handler`로 라우팅
