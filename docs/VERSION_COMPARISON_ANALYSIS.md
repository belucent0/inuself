# PyTorch ROCm 버전 비교 분석: 20251105 vs 20251112/20251113

## 문제 상황

- **20251105 버전**: ✅ 성공적으로 작동
- **20251112 버전**: ❌ `UnicodeDecodeError` 발생
- **20251113 버전**: ❌ `UnicodeDecodeError` 발생

## 오류 상세

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc1 in position 57: invalid start byte
```

**발생 위치**: `torch._C._cuda_init()` 내부 (PyTorch C++ 백엔드)

## 가능한 원인 분석

### 1. **C++ 백엔드 코드 변경**

PyTorch의 C++ 확장 모듈(`torch._C`)에서 GPU 초기화 시 Windows 시스템 정보를 읽는 방식이 버전 간에 변경되었을 가능성이 높습니다.

**1105 버전**:
- Windows 시스템 정보를 읽을 때 안전한 인코딩 처리
- 또는 UTF-8이 아닌 다른 인코딩(예: Windows-1252, CP949)을 사용하여 읽기

**1112/1113 버전**:
- UTF-8로 강제 변환 시도
- Windows 시스템의 기본 인코딩(CP949 등)과 충돌
- `byte 0xc1`는 CP949 인코딩의 시작 바이트일 수 있음

### 2. **GPU 드라이버 정보 읽기 방식 변경**

PyTorch가 GPU 이름과 속성을 읽을 때:

**1105 버전**:
```cpp
// 가상의 C++ 코드 예시
std::string device_name = getDeviceName(device_id);
// Windows API에서 반환된 문자열을 안전하게 처리
```

**1112/1113 버전**:
```cpp
// 가상의 C++ 코드 예시
std::string device_name = getDeviceName(device_id);
std::string utf8_name = convertToUTF8(device_name);  // 여기서 실패
// Windows API가 CP949로 반환한 문자열을 UTF-8로 변환 시도 시 오류
```

### 3. **ROCm SDK 버전 차이**

버전별 ROCm SDK 구성 요소:

| 버전 | ROCm SDK | HIP 버전 | 주요 변경사항 |
|------|----------|----------|--------------|
| 20251105 | 7.10.0a20251105 | 7.1.25443 | 안정적인 인코딩 처리 |
| 20251112 | 7.10.0a20251112 | ? | 인코딩 처리 변경 가능 |
| 20251113 | 7.10.0a20251113 | ? | 인코딩 처리 변경 가능 |

### 4. **Windows API 호출 방식 변경**

PyTorch가 Windows API를 호출하여 GPU 정보를 읽을 때:

**가능한 Windows API**:
- `SetupDiGetDeviceRegistryProperty()` - 장치 속성 읽기
- `EnumDisplayDevices()` - 디스플레이 장치 정보
- DirectX/ROCm 드라이버 API

이러한 API들이 반환하는 문자열의 인코딩이 버전 간에 다르게 처리되었을 수 있습니다.

### 5. **Git 커밋 차이**

**20251105 버전**:
- `git_version = 'eb4ac763d5f24c8b5e2855491853b437767ea061'`
- `hip = '7.1.25443-2383cdb00d'`

**20251112/20251113 버전**:
- 다른 git 커밋 해시
- C++ 초기화 코드에 변경사항 포함 가능

## 왜 1105 버전이 성공했는가?

### 1. **안전한 인코딩 처리**

1105 버전의 C++ 코드가 Windows 시스템 정보를 읽을 때:
- 멀티바이트 인코딩(CP949, Windows-1252 등)을 올바르게 처리
- UTF-8 변환 전에 인코딩 감지 및 변환
- 또는 Windows API의 기본 인코딩을 그대로 사용

### 2. **회귀(Regression) 버그**

1112/1113 버전에서:
- 코드 리팩토링 중 인코딩 처리 로직이 손상됨
- 또는 "UTF-8로 통일"하려는 시도가 실패
- Windows 환경에서 테스트되지 않은 변경사항 포함

### 3. **ROCm SDK 변경사항**

ROCm SDK의 Windows 지원 개선 과정에서:
- 1105: 안정적인 버전
- 1112/1113: 새로운 기능 추가 또는 버그 수정 중 인코딩 문제 발생

## 해결 방법

### 현재 상황 (1105 버전 사용)

✅ **권장**: 20251105 버전을 계속 사용
- 안정적으로 작동
- GPU 가속 정상 작동
- 인코딩 문제 없음

### 향후 대응

1. **PyTorch 이슈 리포트**
   - GitHub에 버그 리포트 제출
   - 1112/1113 버전의 UnicodeDecodeError 문제 보고

2. **버전 업그레이드 시 주의**
   - 새 버전 설치 전 테스트 환경에서 검증
   - 인코딩 관련 변경사항 확인

3. **워크어라운드 (만약 1112/1113을 사용해야 한다면)**
   - Windows 시스템 로케일 변경 (권장하지 않음)
   - 환경 변수 설정으로 인코딩 강제 (효과 제한적)
   - PyTorch 소스 코드 수정 (복잡함)

## 결론

**1105 버전이 성공한 이유**:
1. Windows 시스템 정보를 읽을 때 안전한 인코딩 처리
2. C++ 백엔드의 GPU 초기화 코드가 Windows 환경에 적합
3. ROCm SDK 버전이 안정적

**1112/1113 버전이 실패한 이유**:
1. 인코딩 처리 로직 변경으로 Windows 환경과 충돌
2. UTF-8 강제 변환 시도가 CP949 인코딩과 충돌
3. Windows 환경에서 충분히 테스트되지 않은 변경사항

**권장사항**: 현재 20251105 버전을 계속 사용하고, PyTorch 개발팀에 이슈를 리포트하여 향후 버전에서 수정되기를 기다리는 것이 좋습니다.
